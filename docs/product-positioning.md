# 产品定位与场景规划

记录目标用户场景的判断依据,避免功能规划时凭空造需求或漏掉真实需求。随判断变化持续更新,不是一次性快照。

## 目标场景:办公/专业场景,而非学习场景

不面向"学生自学一本教材"这类学习场景做优化,面向"专业人士处理一批项目材料"这类办公场景。

### 场景筛选公式(2026-07-21 基于真实工具生态调研修订)

**硬门槛**(不满足直接出局):

1. 材料以文件形式到手(PDF/EPUB/音频/图片),手动导入可接受——不需要对接业务系统/自动同步
2. 离线是刚需而非偏好(保密特权/隐私法规/内幕信息/信源保护),且用户群"机构小到用不起企业私有化部署、材料又敏感到不能碰云 SaaS"
3. 单人或小团队作业,无多用户权限/协作需求
4. "一个项目/案件一个库"心智模型成立,检索单库锚定不构成日常阻碍

**价值放大器**(满足越多适配越强):

5. 材料异构且结构复杂(表格/公式/图表/扫描件/录音混合),通用工具解析即碎
6. 答错有真实代价(执业风险/金额/生命/信誉)→页码/时间戳级可回溯引用是刚需
7. 材料量大到人工通读不经济,工作本质是检索/核对/抽取型而非创作型
8. 材料随项目推进持续累积,增量导入省重建成本(加分项)

**反筛选**(出现任何一条即降级):

- 材料全公开无保密压力→云端巨头已服务好,离线卖点失效
- 买方是机构 IT(预算充足、云端接受度高)
- 日常需要跨全部历史项目全局检索→撞单库锚定限制
- 产出需要法定认证形态(认证转写/法庭记录)→只能当工作副本
- 强依赖"谁说的"(多方对质录音的说话人归属)→撞说话人分离缺口(issue #56),其落地前避开此类场景

### 2026-07-21 场景调研结论(三簇真实工具生态调研)

对法律/调查、金融/商业、研究/媒体/医疗三个职业簇做了真实网络调研(工具官网定价、从业者讨论、伦理政策原文),按上述公式评级:

**强适配**(按证据强度排序):

- **刑事辩护(独立/公设辩护律师)**:bodycam/审讯录音+警方报告混合材料量爆炸(超 2/3 公设辩护人每月 10+ 小时人工审看);唯一竞品 JusticeText 云端+机构采购,个体执业者无解
- **中小所民事诉讼 deposition 核对**:Everlaw 约 $2-5K/月把小所挡在门外;"没转写就搜不了音频"是行业公认割裂;ABA Op.512 等伦理意见给"本地 AI 不存在第三方"提供强制性购买理由
- **小型 M&A 买方尽调**(替代原"投资尽调"焦点——公开市场分析师的材料全公开,触反筛选):VDR $10K+/年、Hebbia 约 $10K/席结构性排除小基金;"管理层访谈录音 vs 数据室文件"核对无人做;付费意愿有现成锚点
- **法务会计/舞弊调查**:银行流水/发票扫描件+访谈,结论要出庭(证据级引用刚需);小所可选工具基本仅云端
- **质性研究学者/博士生**:IRB/GDPR 限制受访者录音上云有政策原文级证据;转写 $90-180/音频小时;NVivo 等 QDA 工具贵且 AI 薄
- **调查记者/独立记者**:Guardian 禁用 Otter(配合传票披露)有实锤;Pinpoint 公认"敏感材料不适用";风险是付费意愿低于其他强适配人群

**中适配**:建筑索赔/延误分析(垂直云端竞品已入场)、医疗法律审查(LNC)、小型咨询所、买方分析师自有访谈库、破产管理人、口述历史、纪录片调研。

**临床病例复核:证伪,退出场景叙事**。Nabla $119/月、Freed $99/月等自助订阅已覆盖小诊所,签 BAA 后云端 HIPAA 合规成立,离线卖点失效;实时 scribe 形态也与本产品不符。临床语料降级为学科基准测试集(满足 README 三学科 Hit@5 指标),与 CS 语料同定位,不用于场景叙事;具体书目见下方"三学科基准测试集"一节(原选定的 Nursing Pharmacology 已因 PDF 质量问题放弃,重新选型中)。

### 当前锚定的场景组合

- **法律案件准备**(刑辩/中小所民诉):案卷/证据材料+庭审/询问录音,旗舰能力=跨源核对+精确引用
- **小型 M&A 买方尽调**:数据室文件(合同/报表/扫描件)+管理层访谈录音,旗舰能力=跨源核对+参数化抽取+计算
- 质性研究者/调查记者为后备候选(材料形态重合度最高,但付费意愿/工作流匹配待验证)

## 不做整个企业级知识库平台

多用户、跨数据源持续同步、权限隔离这条路不走,原因是结构性冲突,不只是"暂时没空":

- GPU 互斥锁/`ImportQueue` 是全局单工作线程设计,假设同一时刻只有一个任务在跑,跟企业级并发多用户直接冲突
- `book_id` 单 collection、检索不跨库(见 `docs/book-management.md`),跟"企业整体知识库"要的跨海量文档统一检索方向相反
- 没有权限模型、没有 connector,补齐这些是另一个产品的工作量
- 会跟 RAGFlow(85k star)、Dify(149k star)这类有正经公司全职团队运营的项目正面竞争,现阶段打不过
- 消费级 PC / 离线 / 基于 Ollama 是任务书 A 的硬性交付形态,不是可选项

## 架构定位要点(2026-07-21 补充)

- **硬件档位是伸缩轴不是天花板**:Ollama+GGUF 量化下,向下换小模型支持轻薄本,向上大显存换大模型换更优服务;档位策略属后续扩展,但"用户拿手头机器就能起步"现在就是卖点
- **语料库是可持续生长的活容器**:collection 持久在本机,同一 `book_id` 随时增量追加文件(`get_or_create_collection`+`add_chunks`)。"不需要持续同步/连接器"指不做企业级 connector(自动从 Google Drive/Confluence 等外部系统拉取同步),不是"一次性用完归档"
- **云端 connector 不做**:目标用户的材料本来就以文件离线到手(discovery 硬盘/数据室下载包/录音笔),没有业务系统 API 可对接;做 connector 即滑向企业知识库赛道。唯一值得考虑的轻量形态是本地监视文件夹(指定目录挂到 book,新文件自动进 `ImportQueue`),等真实用户反馈"手动导入烦"再评估,当前不动
- **精度资产**:chunk 带页码(`page_start/end`)、秒级时间戳(`start/end_sec`)、ASR 低置信度标记(`low_confidence`)、六类 `element_type`,引用可回溯到页和秒——对"答错有代价"职业是直接卖点

## 功能不按场景纵向定制,按通用机制横向复用

锚定场景真正需要新建的是通用机制,不是多套代码,场景差异体现在配的语料和参数上:

- **跨来源一致性核对 + 参数化结构化抽取 + calculate 财务健壮性**:详细实现设计已定稿,见 `docs/superpowers/specs/2026-07-21-scenario-features-design.md`
- **拒答严格度配置**:在 issue #40 的相关性阈值机制上加一档"严格程度",高风险场景调高,其余默认

## CS/临床/法学语料现阶段角色:基准测试集,不是场景验证语料

CS 学科的真实办公用途有限——软件工程师日常工作基本不会翻回去查操作系统原理教材,真实用处基本只在"学习/备考"。CS 语料的价值不在于代表一个目标用户场景,而在于它是目前唯一有 ground-truth 核验 + 真实幻觉率数据的完整评测(76 题 QA,`eval/testset/cs/`,issue #40 就是靠它挖出来的)。继续把它当管线质量的基准测试集使用(验证 #17/#40/#11/#10 修复前后的 Hit@5/幻觉率对比),不用于对外的场景定位叙事。临床、法学语料现阶段同此定位——**法学阶段用的 Criminal Procedure 现在只出教材 QA，不配庭审录音、不考跨源核对**；场景功能阶段（见下）如果复用这本书，是另一轮独立的语料补充+出题工作，不是这次学科基准测试集的一部分。

## 与近期优先级的关系(2026-07-21 修订)

1. **临床/法学学科测试集构建**(先行)——消融矩阵要调的旋钮全是领域敏感的:#48 混合检索的关键词信号(法条编号/案件名/药品名/剂量)在法律/临床语料里才密集,CS 教材里稀少;#40 阈值的 cosine 距离分布随领域漂移。只在 CS 上调参必留返工债。测试集的耐久资产是出题+页码级 ground truth,不随 chunker 改动失效,先建的返工成本低

3. **场景功能+场景测试集**——跨源核对/参数化抽取/calculate 健壮性(见上方 spec),用法律+M&A 场景测试集验收
