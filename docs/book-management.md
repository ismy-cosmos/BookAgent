# 书籍管理设计

## 核心模型

**书（Book）是用户在前端自己定义的容器。** 系统不自动推断哪些文件属于同一本书，也不根据文件名或内容判断书籍边界——这个决定完全交给用户。

## book_id

- 创建书籍时由用户命名，作为 `book_id`
- 一旦确定不可更改（ChromaDB 里的所有 chunk 都以 `book_id` 作为 namespace 标识）
- 命名规则：用户自定义，系统侧不做格式限定，但建议简短无空格（如 `ostep`、`civil-law-2024`）

## 添加文件

- 用户在某本书的入口处添加的所有文件，均视为这本书的内容
- 支持 PDF、EPUB、音频（MP3/WAV/FLAC）等所有解析层支持的格式，混合添加没有限制
- 文件只能追加，不支持单独删除某个文件

## 删除

- **最小删除单位是整本书**：删除一本书会清空该 `book_id` 下的所有 chunk（ChromaDB 按 `book_id` 过滤删除）
- 如果用户上传了错误的文件，只能删整本书后重新上传全部文件
- **文件级别删除在技术上可行**（按 `book_id + source_file` 过滤，精确删除对应 chunk，不影响同一本书里的其他文件），预留为未来功能，当前不实现

## 关于"书"与"章节"的边界

系统不做自动区分。用户可以把一本书的多个 PDF 章节文件都添加进同一个 `book_id` 容器，也可以把每章单独建一个 book——这是用户的选择，系统侧透明处理。
