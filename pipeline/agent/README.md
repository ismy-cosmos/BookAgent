# Agent 工具设计说明

## 新增工具时，触发条件不能跟现有工具重叠

现有三个工具（`retrieve`、`calculate`、`get_chunk`）职责互斥：retrieve 是语义探索，calculate 是数值计算，get_chunk 是按 id 精确取回。system prompt 靠"每个工具的触发条件独立描述"来引导模型判断该不该调用，这个机制只在工具之间职责边界清晰时才可靠。

**依据**：issue #17 曾出现"计算 + 书本知识混合型问题"（FIFO 调度平均周转时间这类），模型正确调用了 `calculate` 却跳过了 `retrieve`——根因是两个工具的触发条件在 prompt 里写成并列独立的规则，模型走完一个工具的分支、拿到满意的结果后，不会自动回头检查另一个是否也该触发。这种情况下修法是把 prompt 写得更明确（"每个工具的触发条件独立判断，调用了一个不代表其他的条件不用管"），因为 retrieve 和 calculate 本身职责边界清晰，只是 prompt 没写全。

**如果新工具的能力跟现有工具有交集**（比如某个新工具"看起来 retrieve 也能顺带做、又好像该算个新工具"），单靠把 prompt 写得更明确是压不住的——触发条件本身模糊时，模型没有一个清晰的判断依据，这是设计层面就该避免的问题，不是靠改prompt能补的。评估任何新工具提案时，先确认它的触发条件跟 retrieve/calculate/get_chunk 有没有交集，边界不清晰就先把边界定清楚，不要先加了工具再指望 prompt 讲清楚"什么时候用哪个"。
